Engineering decisions and tests

Preserve the history

Monthly records copy template values instead of reading a changing plan. A database function creates the month and its items in one transaction; a unique user/month constraint prevents duplicate months.

Inspect the schema and snapshot function

Enforce rules in the database

PostgreSQL row-level policies restrict records to their owner. Authenticated users cannot edit months two or more calendar months old; database triggers enforce the cutoff using the profile's timezone.

Inspect the historical-month rules

Test the failure cases

pgTAP tests cover cross-user access, snapshot preservation, and historical locks. Vitest tests cover money, validation, and UI state. The repository also includes an opt-in Playwright flow for a dedicated test account.

Inspect the database tests

Tradeoff: A static React frontend uses Supabase Auth and database APIs, with no custom application server. This keeps hosting simple but retains browser-managed sessions. Offline financial editing is outside the current scope.

API implementation and prototype limits

Read and update locations

The locations GET endpoint returns vehicle IDs, coordinates, and timestamps. The location POST endpoint rejects missing IDs and out-of-range coordinates, then inserts or updates a vehicle record and returns HTTP 204.

Inspect the location API

Connect storage to the map

ASP.NET Core injects an EF Core database context into the controller. Development uses SQLite. Leaflet displays the coordinates returned by the API; a client-side loop posts random offsets to simulate movement.

Inspect the polling and simulation

Define the next iteration

This is a local prototype, not a live GPS service. The next steps are endpoint authentication, safe rendering of vehicle IDs, configurable API URLs, and tests aligned with the actual HTTP responses.

About me

Simple solutions to meaningful problems.

I enjoy the part of software engineering where a tangled problem becomes a clear set of rules: how to preserve a budget's history, clean a dataset, or manage a download.

My approach starts with the fundamentals: understand the inputs, make the logic explicit, and keep the solution easy to follow. In Buddy Budget, that means enforcing ownership and history rules in the database as well as reflecting them in the interface.
